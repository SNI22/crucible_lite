Real-to-Sim Correction — Data Collection Protocol

Source: docs/data_collection_protocol.md (committed 2026-05-16, 91b0a5f). This HTML is a reading rendition with experimental-control highlights added — the markdown is the canonical source.

Variable-control legend — used throughout this document:
  • HOLD CONSTANT Must not change within a session or across re-runs. Drift here invalidates comparisons. This is what you'll be tempted to fudge — don't.
  • MEASURE & LOG Allowed to vary but must be recorded per session (CSV metadata header or paper log). Without the value, the data is not analyzable.
  • FREE Can vary freely, no impact on comparability.
  • CRITICAL Sensitivity-critical control — if this drifts, the comparison breaks even if everything else is solid.

1 · Purpose (recap)

Stage 1 left the simulator-only classifier at 50% sensitivity / 44% FP on real bathroom CSVs. Closing that gap requires fitting each simulator component against real ground truth. This protocol specifies what to measure, in what order, and which signals.py parameter each measurement corrects.

3 · Sample-rate gate — run before every session

Gate check (10 s): capture 10 s of UART output, compute measured_rate_hz = lines / wall-clock-elapsed. Must be ≥ 1000 Hz. If less: abort. INT_MARK is wrong, transport is buffering, or the firmware build is the wrong one. Per Case 1, recordings below 1 kHz are not admissible as Article I evidence.

5 · Per-session mount sanity check (~1 min)

  1. Place housing on tile. Confirm baseplate is flush — no rocking when pushing the cap with a finger.
  2. Place 200 g weight on top platform.
  3. Start UART capture.
  4. Tap tile 30 cm from housing with a fingernail. 5 taps, ~2 s apart.
  5. Stop capture, inspect:
    • Pass: clean impulse, ringdown < 50 ms, no inter-tap oscillation
    • Fail: ringdown > 200 ms (compliant contact), delayed rise (foam), large oscillation between taps (loose preload / rocking baseplate)
If fail: alcohol-wipe the tile, re-seat the housing, repeat. Do not proceed to data collection until sanity check passes. Bad coupling silently contaminates everything downstream.

7 · Variables that matter most — "don't change these mid-study"

If you change any of these between A-phase and B-phase, or between sessions in the same bathroom, your data is not comparable. Pick once and stick:
  • CRITICAL INT_MARK value (must stay 0)
  • CRITICAL tap source (fingernail vs jig — pick one and stick across A2/A3/A4)
  • CRITICAL tap locations (marked with tape, kept across re-installs)
  • CRITICAL operator footwear (barefoot / socks / sole) across A5 + B6
  • CRITICAL drop height across B1/B2/B3/B4
  • CRITICAL "body in path" means operator directly between drop and sensor — not off-axis
  • HOLD preload weight (~200 g, no swap mid-study)
  • HOLD housing (don't re-print between sessions)
  • HOLD sensor (no swap)
  • HOLD door state during baseline + noise recordings
  • HOLD bathroom appliance state during baseline (everything OFF except what's normally on)

Variables that must be measured & logged (but allowed to vary)

  • MEASURE measured_rate_hz per session
  • MEASURE bag / bottle / phone / glass mass
  • MEASURE operator weight (kg)
  • MEASURE tile size + device xy in room
  • MEASURE drop locations xy
  • MEASURE per-event anomalies (bounced off wall, wet floor, etc.)

Variables you can ignore

  • FREE time of day (within reason — avoid 3 AM dead silence vs 9 AM neighbor noise extremes)
  • FREE operator's emotional state, hairstyle, hydration, etc.
  • FREE ambient temperature (within room-temperature range)
  • FREE humidity (within bathroom-normal range)

10 · Open questions to resolve before first execution

  1. Tap source standardization. Fingernail tap is operator-dependent (±50%). Recommended refinement: a small jig — e.g., 10 g steel ball dropped from a fixed 100 mm vertical guide. Optional for first pass; required if A2-A4 repeatability is bad.
  2. Sample-rate metadata. Recommend inline: record session wall-clock start + CSV row count, derive rate post-hoc. Avoids a separate gate-check session.
  3. Storage path. data/ symlinked outside repo with .gitignore to avoid bloating git with large CSVs. Decide once we see actual file sizes.
  4. Legacy CSV admission. The existing ~/Documents/piezo_circuit/bathroom_testing/{catfood,water,step}_201505.csv should be migrated under data/bathroom_legacy/ with metadata headers retro-fitted (operator-attested, not measured). Flag the asymmetry in any v3 report.
  5. Event segmentation tool. Phase B produces 30-minute CSVs with discrete events. Need a tool (script or simple GUI) to extract event windows from log timestamps. Build alongside Phase B execution.
