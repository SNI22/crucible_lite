## Headline outcome — calibration is BLOCKED on a repeatability/fixturing fault

The first physical calibration of A301-1 channel 0 produced physically
impossible data — the sensor is not responding to load in a usable way:

| Force | raw_mean | repeat spread (std) |
|---|---|---|
| 0.52 N | 518 | **301** (5 repeats) |
| 1.02 N | 850 | 21 (4 repeats) |
| 2.01 N | **773** (lower than 1 N) | 119 (5 repeats) |
| 4.97 N | 825 | 15 (4 repeats) |

- Force rises 10× (0.52 → 4.97 N) but raw barely moves (518 → 825).
- 2 N reads **lower** than 1 N — non-monotonic; impossible for a working
  FlexiForce (conductance rises monotonically with force).
- The 53 g level varied by ±301 counts across 5 repeats — non-repeatable.
- Fit: `F = 5.71e-9 · raw^2.94`, adj-R² = 0.239 (criterion 0.998),
  RMS 1.55 N (criterion 0.30 N). REJECTED.

**Leading hypothesis:** the bench **TPU 90A calibration foot is too soft**.
The A301-1 active area is ~9.5 mm; a soft 90A pad larger than the element
deforms and spreads the point load *around* the sensing dot, so the element
sees a small, inconsistent fraction of the applied weight. This produces
exactly the observed symptoms (tiny dynamic range, non-monotonic,
non-repeatable). This is the same contact-distribution concern that the
Bill 0004 hearing circled — except 90A is too soft and spreads load *away*
from the sensor rather than concentrating it.

Other candidates not yet ruled out: wrong channel mapping, sensor not
seated/preloaded, conditioning-circuit gain too low.

**Invalid artifact:** `docs/calibration/ch0_20260521.json` was written with
`acceptance.passed: false` (inadmissible under Bill 0002 Part 7). Left
untracked / not committed; delete or overwrite on next valid run.

## Diagnostic next step (next session)

Run the live monitor added to the calibration runner:

```
python3 scripts/calibrate_a301_1.py --channel 0 --monitor
```

Four checks, in order:
1. Finger-press the sensor — does raw jump cleanly (100s–1000s of counts)
   and return to baseline on release?
2. Press **directly on the A301-1 element** vs **through the TPU 90A foot** —
   if direct swings big and clean but through-foot barely moves, the soft
   foot is confirmed as the culprit (decisive test).
3. Confirm channel mapping — press each foot, verify ch0 responds to the
   foot believed to be ch0.
4. Repeatability — place 204.9 g, lift/replace 3×; readings should land
   within a few % (this session saw ±300 counts).

**Likely fix if foot is confirmed:** concentrate the load onto the ~9.5 mm
active area — a rigid load puck of matched diameter on the sensor (Tekscan's
recommendation; what Attorney-B argued in the Bill 0004 hearing), or a small
rigid disc bonded on top of the sensor under the foot. NOTE: this would
change the fixturing decision made in Bill 0004 (TPU 95A pad) — a rigid
concentrator is a different fixture and would need a Bill amendment or a new
Bill once the diagnosis is confirmed.

## Tools built this session

  calibration runner.
  - Self-contained pyserial reader for the DAQ 18-byte frame
    (0xAA / 8×uint16-LE / 0x55 @ /dev/ttyUSB0 115200), per
    `toolchain_config.md` DAQ Serial Frame.

    `raw_std` = spread across repeats when >1, else window std.
  - `--monitor` live raw readout for sensor-response diagnosis.
  - Defaults: 4 single weights (53 / 103.9 / 204.9 / 507 g, no stacking),
    FS 15 N, 100 Hz. Plain Bill 0003 dead-weight path — no TPU 95A record
    (feet are 90A), C1–C4 conditions not enforced (operator's instruction).
  - Fits `fit_power_law` + `check_acceptance`, writes per-channel JSON.
