   not been characterised in terms of how it can be controlled. Most lab
   MTS frames have proprietary GUI software (MTS TestSuite, Instron
   Bluehill, etc.) and no out-of-box Python API. Need from the lab:
   (a) MTS model, (b) vendor software in use, (c) whether any SDK /
   Modbus TCP / OPC-UA / Python scripting is configured. The path
   forward depends on the answer:
   - **API available:** implement a concrete `MTSDriver` against it;
     `c1_feasibility_check()` already runs end-to-end against the Mock
     and will run against the real driver.

     exported force-time log from the vendor software and produces the
     same `C1Report` structure.
